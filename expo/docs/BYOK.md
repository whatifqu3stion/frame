# Full-access BYOK edition

This branch replaces the subscription/demo-paywall product with one full-access app. No RevenueCat SDK, purchases, subscription checks, or plan selection remain in the active runtime. Standard Expo tooling replaces the Rork Metro wrapper, which injected analytics and development providers. Local library, playback, sessions, and profile controls remain available. Google account sign-in and subscription import are retired. Product boundaries (finite Today, source/profile caps, sessions with endings, and Managed profile approvals) remain independent of payment.

The personal-use limits and search boundaries are documented in [PERSONAL_USE.md](./PERSONAL_USE.md).

## Setup

1. Use the native iPhone or Android app. Setup opens at key entry. Select YouTube or Gemini and paste the matching key. Both tabs show whether a key has been verified. Each field has an optional illustrated setup guide. Continue through the viewing study, welcome and comparison. Choose library topics, then optionally add up to eight custom interests. Existing connections are recognized; you may defer either service. Select interests and tap **Find my picks** to explicitly request reviewed suggestions. The first group opens on Today. Each group features one large print; tap another print to bring its title and actions forward without starting playback or generating again. **Add a creator I know instead** bypasses discovery. You can skip setup and open Today. With interests selected and keys missing, Today offers **Connect my keys** beside weekly picks. Missing-key recovery returns to the source entry or picks that requested it.
2. In Google Cloud, enable **YouTube Data API v3**. Create a dedicated key and restrict its API access to YouTube Data API v3. Paste it into Frame and choose **Verify & save**.
3. For optional AI suggestions, create a separate Gemini key restricted to the **Generative Language API**. Set appropriate provider quotas, review billing, then verify and save it in Frame. Budget alerts do not impose a spending cap.
4. Select interests. In **Sources → Discover**, choose **Generate this week’s picks**. One bounded Gemini request proposes up to 24 handles. Frame verifies each source through YouTube, inspects up to 36 recent upload entries in pages of 12, then makes at most one Gemini quality-review request per eligible source (at most 25 Gemini calls per attempt, plus YouTube requests). Review stops when 12 sources qualify. The current weekly focus of interests (including custom topic labels) and bounded public channel/video metadata go to Gemini; no profile identity, history, or saved library is sent. Sources without enough substantive long-form evidence are omitted. AI judgments are based on metadata, not watching full videos, and are not a safety or quality certification. See DISCOVERY_QUALITY.md for the versioned rubric.

Both Gemini requests specify JSON schemas and still undergo local validation. Malformed or duplicate proposals are skipped individually; an entirely malformed nonempty proposal response is an error, not an empty edition. If a later provider request fails, already verified and quality-approved picks are saved as the week’s edition, with a warning identifying the failed stage. There is no automatic retry or refill. Cancellation, profile changes, and key changes discard unfinished work. If no picks qualified before a provider error, the error is shown instead of claiming that no sources met the quality bar.

For live-testing reports, share the failure stage, provider, HTTP status (when available), model name, and app build number. Never include a key or raw provider response. Local storage failures and the cooldown have their own messages rather than suggesting a key problem.

YouTube verifies a key with one channels request. Gemini reads the configured model’s metadata and checks that it supports content generation. This request does not spend generation tokens or test the project’s generation quota. The configured model is `gemini-3.5-flash-lite`.

Direct provider HTTP failures identify the provider and HTTP status without displaying Google's raw response. A rejected request (400) is not proof of a bad key; check project prerequisites and Frame's request compatibility. For Gemini access failures (401/403), check the key's Generative Language API restriction and the project's access, eligibility, and billing status in Google AI Studio. Billing (402), quota (429), and service/model availability failures are reported separately. YouTube verification failures during generation no longer all appear as rejected access. Do not remove API restrictions or enable paid billing just to dismiss an error; identify the failure first.

Google account sign-in and subscription import are disabled, even when old OAuth client IDs are configured. Add sources by channel link or @handle. Existing followed sources are preserved. Earlier installations with a saved Google credential retain a disconnect action in Settings; no new subscription reads or imports are permitted. API keys do not grant access to private subscriptions.

## Storage and requests

- Keys use Expo SecureStore with a separate keychain service and `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. The Expo SecureStore plugin excludes its Android entries from backup. There is no plaintext or browser-storage fallback.
- On localhost only, the development browser preview can verify real keys with Google and hold them in tab memory until refresh or close. Hosted previews disable entry. No browser persists provider keys. Do not paste keys into source, environment files, support status, screenshots, or test fixtures.
- Keys are device-wide and Owner-managed; all local profiles can use YouTube metadata within their existing content permissions. Only the Owner can generate AI suggestions or change keys. Stored values are never displayed or loaded into React Query state.
- Direct requests use fixed HTTPS Google endpoints, `x-goog-api-key` headers, no URL credentials, no cookies, redirect rejection, bounded timeouts, and no automatic retries. Provider error bodies and transport exceptions are not surfaced or logged.
- YouTube source feeds deduplicate requests and cache metadata in memory for 15 minutes; source IDs, result sizes, and concurrency are bounded. Existing database metadata-retention rules still apply.
- Reading onboarding or Discover never generates AI content. An explicit generation action is required. A generated pool is reused for its profile throughout the UTC week, including after interest edits. Library topics can all be selected. Each profile can add up to eight custom topics; at most 12 topics rotate into each weekly request. Custom labels are treated as untrusted topic data and cannot override the quality rubric. Attempts have a 60-second cooldown, capped output, and no tools or automatic continuation. This is not a provider billing cap.
- Replace/remove cancels requests and invalidates the in-memory feed cache. Successful validation is required before replacing an existing key. Removing a key affects future requests, not work already accepted by Google. Existing library links and local metadata remain.
- Erase all Frame data removes provider keys before resetting the library. A native secure-storage failure prevents the reset from claiming success. Revoking the provider key is a separate action in Google Cloud/AI Studio. iOS keychain values can survive app uninstall; use in-app removal or provider revocation.

## Security boundary and release checks

BYOK credentials are the user's credentials, not bundled developer secrets. Device secure storage protects persistence; the app must temporarily hold a key in memory to call Google. A compromised device, debugger, or malicious app update can extract it. No mobile BYOK implementation can promise otherwise. Use dedicated, restricted, revocable keys. Never distribute shared app-owned provider secrets in the client.

Before shipping, verify on physical iOS and Android devices: secure save/restart/remove; restricted YouTube and Gemini keys; invalid, revoked, quota-exhausted keys; offline and stalled requests; backgrounding while editing/generating; profile switch and Owner PIN; full reset including secure-storage errors; backup/restore behavior; legacy Google credential cleanup; generated-source verification; and provider billing visibility. Automated tests use fake keys and mocked provider responses; they do not establish live API or device acceptance.

Official references: [Expo SecureStore](https://docs.expo.dev/versions/latest/sdk/securestore/), [Google API key headers](https://docs.cloud.google.com/docs/authentication/api-keys-use), [Gemini key guidance](https://ai.google.dev/gemini-api/docs/api-key), [Gemini model](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite), [YouTube channels](https://developers.google.com/youtube/v3/docs/channels/list), [YouTube uploads](https://developers.google.com/youtube/v3/docs/playlistItems/list).

### First discoveries and waiting

The explicit search can now publish a durable checkpoint after three fully reviewed picks. Onboarding opens those picks while the same bounded search continues; opening a video or Today does not start another search. The first reveal and an issued first page keep their ordering as further reviewed picks arrive. A pool issued during that search may grow only until that search settles.

Stop, app suspension, a profile/interest change, or a provider-key change cancels remaining work. Already published picks remain saved; before the first checkpoint, cancellation publishes nothing. An interrupted search is not automatically retried. The UI reports actual stages and accepted-pick counts, never a fabricated percentage or completion estimate. A quiet thank-you appears after 12 seconds; it adds no artificial wait. Reduce Motion removes the floating movement, and inactive screens pause it.
